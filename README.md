# Contact Centre WFM Dashboard (Power BI + web version)

![Data](https://img.shields.io/badge/data-simulated-lightgrey) ![Power BI](https://img.shields.io/badge/Power%20BI-DAX-F2C811?logo=powerbi&logoColor=black) ![Chart.js](https://img.shields.io/badge/web-Chart.js-FF6384) ![License](https://img.shields.io/badge/license-MIT-blue)

**Live dashboard:** https://mail4rahulwork-sketch.github.io/powerbi-contact-centre-wfm-dashboard/

This is the kind of daily view I'd want on my screen as a WFM analyst: one page that tells you if service level is holding, whether the forecast was right, and if you had enough people on the floor. If something went wrong, it should show you why.

It covers three queues (Voice, Chat, Email) from July to October, including an 11-day festive peak where the forecast under-called the volume.

> All data here is made up (generated by `generate_data.js`). No company or customer data is used.

## What's on the page

| Section | What it answers |
|---|---|
| KPI tiles | Service level, abandon rate, forecast accuracy, AHT, staffing gap, shrinkage vs plan, adherence, CSAT, days SL met |
| Service level vs target | Which days we missed, and by how much |
| Offered vs forecast | Was the miss a forecast problem? |
| Actual vs required FTE | Did we have the people we needed? |
| Shrinkage vs plan | Were people off the floor more than planned? |
| Intraday heatmap | Which weekday and hour carry the load |

You can filter by queue and by period (normal days vs the festive peak).

## What I found

| | Normal days | Festive peak |
|---|---:|---:|
| Service level | 82.3% | 54.5% |
| Abandon rate | 3.5% | 8.8% |
| Forecast accuracy | 95.3% | 85.5% |
| AHT | 417 s | 440 s |
| Shrinkage over plan | +1.7 pts | +5.5 pts |
| Days service level met | 56% | 0% |

- Normal days are fine. The trouble is the peak: volume came in about 35% higher but the forecast only planned for 15%.
- It wasn't only volume. Contacts got longer and more people were off the floor, so the staffing gap was bigger than the forecast miss.
- Mondays are the heaviest day, and every queue has two busy spells (late morning and early evening). Keep breaks and training away from those hours.
- For the next peak: base the uplift on last year's actual peak, freeze leave and training for that window, and plan a temporary batch.

## Files

```
├── index.html                       # web dashboard (Chart.js), served on GitHub Pages
├── dax_measures.md                  # DAX measures for the Power BI model
├── generate_data.js                 # makes the simulated data (seeded, so it's repeatable)
└── data/
    ├── daily_queue_performance.csv  # one row per date x queue
    └── intraday_profile.csv         # average contacts per weekday x hour x queue
```

## Data dictionary (daily_queue_performance.csv)

| Column | Meaning |
|---|---|
| Forecast_Volume / Offered / Handled / Abandoned | Contacts forecast, arrived, answered, lost |
| Answered_Within_SL / SL_Target | Contacts answered in target time, and the target (80/20 voice, 85% chat, 90% email in 24h) |
| AHT_Sec | Average handle time in seconds |
| Required_FTE / Scheduled_FTE / Actual_FTE | People needed, rostered and actually available |
| Planned_Shrinkage / Actual_Shrinkage | Share of paid time not available for contacts |
| Schedule_Adherence / CSAT | Adherence to schedule, customer satisfaction (1 to 5) |

## Using it in Power BI

1. Load both CSVs in Power BI Desktop (Get data → Text/CSV).
2. Add a date table and mark it as the date table.
3. Paste the measures from `dax_measures.md`.
4. Build the same visuals as the web version: KPI cards, line charts by date, and a matrix (weekday x hour) with conditional formatting for the heatmap.

## Run the web version locally

Just open `index.html` in a browser. To regenerate the data: `node generate_data.js`.
